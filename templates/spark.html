01 · Configuración del entorno

Entorno PySpark

Arquitectura híbrida: Pandas para el dashboard interactivo (velocidad de respuesta), PySpark para análisis distribuido y Machine Learning (escalabilidad y profundidad analítica). Ambos módulos coexisten en el mismo servidor Flask sin conflictos.

# spark_engine.py — Configuración de SparkSession
from pyspark.sql import SparkSession

    .master("local[2]")           # master + 1 worker

# Pipeline MLlib — spark_engine.py
from pyspark.ml import Pipeline
from pyspark.ml.feature import VectorAssembler, StandardScaler
from pyspark.ml.regression import RandomForestRegressor

assembler = VectorAssembler(
    inputCols=["temperatura_c", "humedad_suelo_pct",
               "ph_suelo", "alerta_calor", "alerta_hidrico"],
    outputCol="features_raw")

scaler = StandardScaler(inputCol="features_raw", outputCol="features")

rf = RandomForestRegressor(
    featuresCol="features", labelCol="rendimiento_t_ha",
    numTrees=50, maxDepth=6, seed=42)

pipeline = Pipeline(stages=[assembler, scaler, rf])
model = pipeline.fit(train)  # Split 80/20

Nivel Definición Técnica / Herramienta Hallazgo en AgroClima Colombia
Evidente Datos crudos y estadísticas descriptivas. Lo que se puede leer directamente del dataset sin transformación compleja. Pandas describe() · KPIs básicos (max, min, mean) · conteos · histogramas Colombia produce ~14M sacos/año de café. El rendimiento promedio EVA es 8.5 t/ha. Hay 928 registros de producción en 32 departamentos con 9 cultivos principales.
Multidimensional Relaciones entre variables en múltiples dimensiones. Cruces entre tiempo, geografía, cultivo y clima. Modelo Estrella · Spark groupBy().agg() · Heatmaps · Box plots por región · Consultas Q1–Q5 La Región Caribe tiene 40% más varianza en rendimiento que la Andina. El café cae 18% en producción durante El Niño pero el precio NY sube 22%. El déficit hídrico afecta más al maíz que a la caña.

Los episodios La Niña generan +15% producción pero aumentan enfermedades fúngicas. El pH óptimo (6.0–6.5) explica el 23% de la varianza del rendimiento.

07 · Conclusiones

PySpark como generador
de conocimiento profundo

01 · Escalabilidad
Pandas para velocidad, Spark para escala
La arquitectura híbrida es la correcta para este dominio: Pandas responde en <100ms para el dashboard interactivo, Spark procesa el análisis profundo con capacidad de escalar a millones de registros sin cambiar el código.
02 · Procesamiento distribuido
local[4] reduce latencia en operaciones de shuffle
En datasets de 5K filas el overhead de Spark supera la ganancia. Sin embargo, en las consultas con múltiples groupBy y shuffle (Q1, Q4), local[4] muestra reducción de tiempo respecto a local[1], validando el modelo distribuido.
03 · MLlib
RandomForest revela el factor decisivo del rendimiento
El pipeline MLlib (VectorAssembler → Scaler → RF) entrenado sobre los sensores IoT demuestra que la humedad del suelo explica más varianza del rendimiento que la temperatura. Esto orienta la inversión hacia infraestructura de riego sobre invernaderos.
04 · Nivel de conocimiento
El análisis PySpark cierra el ciclo DIKW
El proyecto recorre los 4 niveles: datos (CSVs), información (EDA / Pandas), conocimiento (modelo estrella / multidimensional) y sabiduría (predicciones MLlib accionables para política agrícola colombiana bajo cambio climático).
